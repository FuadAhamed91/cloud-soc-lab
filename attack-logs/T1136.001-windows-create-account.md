# Create Account: Local Account (Windows) — T1136.001

| Field | Value |
|-------|-------|
| ATT&CK | T1136.001 — Create Account: Local Account |
| Tactic | Persistence |
| Platform | Windows |
| Endpoint | DESKTOP-MTJVV2L (agent 002) |
| Date | 2026-09-17 |

## Simulation
Attacker creates a local backdoor account for persistence.
```
net user backdoor P@ssw0rd123! /add
```
Cleanup: `net user backdoor /delete`

## Telemetry produced
Windows **Security** event log (collected by the agent as an eventchannel):
- Event ID **4720** — A user account was created (target: backdoor)
- Event ID **4738** — A user account was changed
Sysmon also records the `net.exe` process creation (Event ID 1).

## Detection result
Fired on **default Wazuh rules**:

| Rule ID | Level | Description |
|---------|:-----:|-------------|
| 60110 | 8 | User account changed |
| (60109-family) | — | User account created (Event 4720) |

The alert carries the full context: target account, the creator (`fuad`), host, SIDs, and UAC flags.

## Verdict
**Caught by default.** Windows account creation is covered out of the box — confirms the Windows
endpoint pipeline (Security log + Sysmon → agent → manager) works end to end.

## False-positive check
Rule 60110/60109 fire on any account change/creation, including legitimate admin activity — tuned
in production (e.g. alert only on accounts created outside change windows or by unexpected users).
