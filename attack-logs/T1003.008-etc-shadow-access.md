# OS Credential Dumping: /etc/shadow — T1003.008

| Field | Value |
|-------|-------|
| ATT&CK | T1003.008 — OS Credential Dumping: /etc/passwd and /etc/shadow |
| Tactic | Credential Access |
| Platform | Linux |
| Endpoint | kali (agent 001) |
| Date | 2026-09-16 |

## Simulation
Attacker reads the password-hash file to crack credentials offline.
```
sudo cat /etc/shadow > /dev/null
```
Cleanup: none (read-only, no state change).

## The gap (default behaviour)
Default Wazuh only produced a routine sudo alert — the credential theft is invisible as such:

| Rule ID | Level | Description |
|---------|:-----:|-------------|
| 5402 / 5403 | 3–4 | Successful / first-time sudo executed |

The command line (`/usr/bin/cat /etc/shadow`) is *present* in the event but nothing flags it
as credential access. An analyst would scroll past a level-3 sudo alert.

## The detection (custom rule)
Authored `detections/wazuh-rules/local_rules.xml` rule **100010** (+ portable Sigma in
`detections/sigma/`). It chains off the sudo rules and elevates any command touching
`/etc/shadow` to **level 12**, mapped to T1003.008.

## Validation (wazuh-logtest)
- Attack `sudo cat /etc/shadow` → **rule 100010, level 12**, mitre T1003.008 ✅
- Benign `sudo apt update` → rule 5403, level 4 (rule 100010 did **not** fire) ✅ no false positive

## Verdict
**Gap closed with a custom rule.** Default missed it (as credential access); custom rule 100010 detects it.

## False-positive check / limitations
- Benign sudo does not trigger it (verified).
- Limitation: catches access **via sudo** where the command contains `/etc/shadow`. A root shell
  reading it without sudo, or copying then reading elsewhere, would evade it.
- Hardening follow-up: an auditd file watch (`-w /etc/shadow -p r -k shadow_read`) would catch
  *every* read regardless of method — a stronger v2 of this detection.
