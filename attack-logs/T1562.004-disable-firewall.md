# Impair Defenses: Disable or Modify System Firewall — T1562.004

| Field | Value |
|-------|-------|
| ATT&CK | T1562.004 — Impair Defenses: Disable or Modify System Firewall |
| Tactic | Defense Evasion |
| Platform | Linux |
| Endpoint | kali (agent 001) |
| Date | 2026-09-16 |

## Simulation
Attacker turns off the host firewall to move freely.
```
sudo systemctl stop ufw     # (also matches: ufw disable, iptables -F, nft flush ruleset, systemctl disable ufw)
```

## The gap (default behaviour)
Default Wazuh only produced a routine sudo alert (rule 5402/5403, level 3–4). Firewall tampering
was not flagged as a security event.

## The detection (custom rule — authored in the Wazuh dashboard editor)
`detections/wazuh-rules/local_firewall_rules.xml` rule **100020** (+ Sigma in `detections/sigma/`).
Chains off the sudo rules and matches several firewall-kill commands, raising a **level 10**
Defense-Evasion alert mapped to T1562.004.

## Validation
- `wazuh-logtest` on `sudo ufw disable` → rule 100020, level 10, mitre T1562.004 ✅
- Live: `sudo systemctl stop ufw` on kali → **rule 100020 fired** on the manager ✅

## Verdict
**Gap closed with a custom rule.**

## False-positive check / limitations
- Command-string matching: catches the listed firewall-kill commands via sudo. An admin
  legitimately reconfiguring the firewall would also trigger it (expected — worth an alert).
- Evasion: a method not in the match list, or done without sudo, would slip past. A stronger v2
  would watch the firewall service/unit state directly (auditd or systemd monitoring).
