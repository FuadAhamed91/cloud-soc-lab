# Create Account: Local Account — T1136.001

| Field | Value |
|-------|-------|
| ATT&CK | T1136.001 — Create Account: Local Account |
| Tactic | Persistence |
| Platform | Linux |
| Endpoint | kali (agent 001) |
| Date | 2026-09-16 |

## Simulation
An attacker with root creates a local user for persistent access.
```
sudo useradd -m -s /bin/bash svc-backdoor
```
Cleanup: `sudo userdel -r svc-backdoor`

## Telemetry produced
Collected via **journald** on the agent. The `useradd` binary logs the account and group
creation; `sudo`/PAM log the privileged execution:
```
kali sudo[19813]: kali : TTY=pts/0 ; USER=root ; COMMAND=/usr/sbin/useradd -m -s /bin/bash svc-backdoor
kali useradd[19816]: new user: name=svc-backdoor, UID=1002, GID=1002, home=/home/svc-backdoor, shell=/bin/bash
```

## Detection result
Fired on **default Wazuh rules** — no custom rule required:

| Rule ID | Level | Description |
|---------|:-----:|-------------|
| 5902 | 8 | New user added to the system |
| 5901 | 8 | New group added to the system |
| 5402 | 3 | Successful sudo to ROOT executed |

The alerts also carry the full command line and the invoking user (`kali` → root via sudo).

## Verdict
**Caught by default.** Account creation is covered out of the box.

## False-positive check
Rule 5902 fires on *any* account creation, including legitimate admin activity. In production
this would be tuned — e.g. surface only accounts created outside a change window, or created by
unexpected users — rather than alerting on every `useradd`. For a lab, level 8 is appropriate.
